# Studio builder audit: issue #57

Baseline: `6ebdf13` (approved main, 28 October 2026). Feature branch: `feat/studio-2-foundation`.

## Scope and evidence

This audit precedes the editor implementation. The entire approved site is the authority, with `reference/CONCEPT_12_APPROVED.html` as its original reference. Newer approved motion, service inventory, shared closing CTA and portfolio changes take precedence. Required source documents and brand guide pages 2, 3 and 6-10 were read; the PDF pages were rendered and visually inspected.

There are 12 authored records, 52 source sections, three cinematic case experiences and 68 service expertise entries. `/services/` is a retained compatibility alias rather than a new design. Browser baseline capture runs on the real Next.js dev app in isolated contexts at 320/390/768/1024/1440/1920. It does not inspect, clear or modify the owner's Chrome storage. Raw DOM/source inventories supplement the screenshots; a CSS class is not proof that an editor control works.

## Actual defects versus enhancements

| Severity | Finding | Classification | Required correction |
|---|---|---|---|
| P1 | Arbitrary new pages fall back to the homepage route/render template; generic nested blocks cannot be built/rendered consistently. | Functional gap, not a missing paint treatment | Versioned component tree + real shared generic renderer, explicit route/build integration. |
| P1 | Canvas selects only `[data-section]`; most visible descendants, layout and CSS imagery have no owner-facing binding. | Functional coverage gap | Typed binding registry, element hit testing, truthful contextual controls. |
| P1 | Local upload control asks for a PHP backend and cannot place a new local asset. | Incomplete workflow | Validated media repository, durable blobs, actual canvas URLs, import/export. |
| P1 | Local browser previews are not static route/SEO deployment; PHP publish only updates JSON. | Release architecture gap | Separate authenticated release protocol and immutable static-generation adapter. Never call browser preview live publishing. |
| P1 | Legacy backend has one administrator, no optimistic revision token, no approval/release state or protected shared preview. | Multi-owner/security gap | Roles, atomic compare-and-swap, audit/revisions, secure preview and release/rollback. |
| P1 | Existing compatibility reads may reconcile historical defaults and write recovery keys; the old backup utility omits several recovery keys and reparses raw strings. | Preservation risk | Byte-preserving, SHA-256-verified backup before conversion; no automatic overwrite of legacy keys. |
| P2 | Undo is page-only and capped; redo, import/export comparison, revision restore and concurrent-tab detection are missing. | Product gap | Transaction model, bounded history, verified backups and conflict UI. |
| P2 | Inspector exposes implementation names and broad unlabelled numeric panels. | UX/accessibility gap | Branded workbench, contextual groups, units/inheritance/help, keyboard controls. |
| P2 | `safeHref` is a link helper, not a complete media/upload sanitizer; a safe editor needs separate policies. | Hardening requirement | Typed/allowlisted styles and media, validated MIME/magic/decode, no executable SVG/HTML uploads. |

## Data, security and durability assessment

The four draft/preview localStorage records, both recovery records and all other `showset-*` historical keys are origin-specific. Git does not back them up. The Phase 1 read path must not call the side-effecting compatibility adapter before a verified raw backup exists. A new versioned store is separate; no automatic destructive migration is authorised. Old editor and keys stay available for rollback.

Existing PHP has sessions, CSRF checks, prepared SQL, MIME validation and rate limits. It is not the current Vercel runtime. Host-only Origin comparison ignores scheme/port; single-role auth, lost-update prevention, release approval, media immutability and audit/restore need work. Credentials remain developer-managed. Phase 1 is loopback-only and makes no remote-auth or shared-storage claim.
